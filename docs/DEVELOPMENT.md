# 开发说明

## 环境

扩展本体是原生 JavaScript，不需要 npm 安装或编译。测试使用 Node.js 22+；打包脚本使用 Python 3.9+ 标准库。运行扩展只需要浏览器，不需要这些开发工具。

## 结构

```text
extension/
  manifest.json       扩展声明、权限和脚本加载顺序
  background.js       会话任务、队列与回答标签页激活
  core.js             网页识别、上下文截取与问题组装
  content.js          阅读小窗、桌宠及回答页执行逻辑
  stream-watch.js     页面世界的既有聊天流生命周期观察
  stream-decoder.js   可见正文补丁解码，不依赖后台 DOM 渲染
  pet-catalog.js      100 段动画的本地文件、名称与分类
  ui.js               Shadow DOM 中的样式
  assets/             当前发行素材、来源和许可证
preview/              预设回答的交互示例
tests/                Node.js 模拟环境测试
scripts/release.py    公开文件白名单、校验与发行打包
docs/                 安装、使用、排查和发布说明
```

`stream-decoder.js` 和 `stream-watch.js` 在 document_start、MAIN world 按顺序加载，流监听只在专用回答页启用。其他脚本在 document_idle、扩展隔离环境加载。回答页不挂载小窗和桌宠。

## 运行测试

在仓库根目录执行：

```sh
node --test tests/*.test.cjs
```

覆盖上下文预算、排队与修订号、首问激活与请求发出后返回、后续不切页、流式同步、完成状态、输入法保护、主题和形象尺寸、动画状态及失败恢复。

这些是模拟 DOM / 浏览器 API 的测试，不能证明真实网页选择器、后台初始化、视频透明度或动画流畅度。测试命令不需要登录，也不会向模型发送请求。

## 本地验证

按 [安装文档](INSTALL.md) 加载 `extension/`。修改脚本后重新加载扩展，并刷新 DeepSeek 阅读页和专用回答页。

发布前至少手动检查：

1. 打开小窗可预加载未激活的回答标签页，首问切过去，请求发出后立即返回；后续问题复用且不切页。手动切到第三标签后不会强制返回。关闭回答页重新提问会再初始化一次。
2. 回答中连续追问会排队，换词后旧回复不会覆盖新选区。
3. 改变上下文范围、切换明暗主题，刷新后偏好恢复。
4. pet-with-you 角色默认中号，手动选择小／中／大尺寸后刷新，确认偏好恢复。
5. 待机 → 思考 → 待机、手动动作结束恢复、视频透明度和错误备用图。
6. 退出后桌宠与小窗消失，选中文字再点追问可恢复。
7. 真实回答页的回答结束后，小窗合理收尾；网页暂停与错误不会被当成永久忙碌。
8. 随机动作间隔可以选择关闭或 1／3／5／10 分钟，并在刷新后保留；回答中、手动播放、隐藏页面、退出时跳过当次触发。

`preview/index.html` 使用预设回答，可用于理解界面交互，不验证真实 DeepSeek 发送、登录或完成识别。浏览器是否允许直接加载本地视频取决于环境；出现本地资源限制时以扩展加载后的页面为准。

## 开发约束

- 访问范围限于 `chat.deepseek.com`，新增权限需说明实际用途。
- 不读取 Cookie 或账户令牌，不记录私人对话，不覆盖网页输入框中的其他草稿。
- 不主动绕过站点登录、验证或限流。
- 动画仅从本地目录加载；点播不能发起模型请求。
- `petSize`、`randomActionMinutes` 等偏好变更时考虑旧值兼容；小窗历史当前不持久化。
- 修改动画分类时确保目录、清单与许可一致。素材新增必须有明确来源和许可范围。

## 打包

```sh
python scripts/release.py
```

打包后可在临时目录解压源码包，独立运行同一测试命令，验证其不依赖本机其他目录。详见 [发布说明](RELEASING.md)。
